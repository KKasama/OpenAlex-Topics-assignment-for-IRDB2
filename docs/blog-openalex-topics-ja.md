# IRDB 日本語論文への OpenAlex Topics 自動付与 ― 多言語埋め込みと BM25 アンサンブルによるアプローチ

**iGroup Japan　笠間和喜**

---

## はじめに

OpenAlex は、世界最大規模のオープンな学術論文データベースです。2024年に導入された **Topics** 機能は、4,516 の研究トピックを階層的に整理した分類体系であり、各論文に最大3件の Topic が付与されます。Topics の階層構造は以下のとおりです。

```
Domain（4件）
  └── Field（26件）
        └── Subfield（252件）
              └── Topic（4,516件）
```

この Topics 体系は、研究動向の把握、関連論文の発見、研究評価など多岐にわたる用途が期待されており、図書館や研究機関にとって非常に重要なメタデータです。

一方、**日本の機関リポジトリデータベース（IRDB）** には約 249 万件の日本語論文が収録されています。これらの論文に対して OpenAlex は Topics を付与していますが、現状では**医療論文が「軍事技術」に分類されるなど、明らかに不適切な付与が多数発生**しています。本記事では、この問題に取り組んだ研究開発の経緯と成果を報告します。

---

## なぜ日本語論文への Topics 付与が難しいのか

OpenAlex の Topics 付与アルゴリズムを分析した結果、以下の根本原因を特定しました。

**① 学習データの言語偏り**  
OpenAlex の分類モデルは、主に英語の学術論文を対象として学習されています。日本語のテキストに対する識別能力が低く、英語専用の特徴が優先されます。

**② 引用関係への依存**  
OpenAlex は引用ネットワークの情報も使用していますが、日本語論文は国際論文との引用関係が希薄なため、この情報が機能しません。

**③ 埋め込み空間のミスマッチ**  
モデルのファインチューニングによって多言語対応能力が失われており、日本語テキストが意味空間の誤った位置にマッピングされます。

これらの問題により、日本語論文では「タイトルや要旨の言語的意味」が正しく捉えられず、トピック分類が機能しません。

## 開発したアプローチ

### v1：多言語埋め込みモデルによるセマンティック検索

まず、**多言語対応の文埋め込みモデル** `multilingual-e5-base`（intfloat 社、278M パラメータ）を活用した手法を開発しました。

この手法の骨子は以下のとおりです。

1. 4,516 件の OpenAlex Topic の説明文（英語）を埋め込みベクトルに変換し、FAISS インデックスを構築
2. 対象論文のタイトルと要旨を同じモデルでベクトル化
3. コサイン類似度による最近傍検索で上位 Topic を取得

`multilingual-e5-base` は日本語と英語を同一の意味空間にマッピングする能力を持つため、翻訳なしで日英クロスリンガルな検索が実現します。1,000 件のテストサンプルで評価した結果、Primary 一致率 **20.6%**、Top-3 Hit 率 **34.0%** を達成しました。

### v2：BM25 アンサンブル

次に、キーワードマッチングの手法 **BM25** を組み合わせたアンサンブル手法（v2）を開発しました。論文テキストに含まれる英語の専門用語・略語（"COVID-19"、"CRISPR" など）は、セマンティック検索より直接的なキーワードマッチングで対応できます。

```
最終スコア = 0.90 × 埋め込みスコア + 0.10 × BM25 スコア
```

BM25 には CJK 文字のバイグラム分割を採用し、日本語テキストにも対応させました。重み比率の探索（0.10 / 0.15 / 0.25）では精度への影響は軽微でしたが、スコアの信頼性の観点から BM25 重み **0.10** を採用しました。Primary 一致率 **22.7%**、Top-3 Hit 率 **35.1%** を達成しました。

### v3：機械翻訳の試み

「日本語テキストを英語に翻訳してから埋め込む」というアプローチも検討しました。翻訳モデルとして、OPUS-MT（ローカル）と Gemini 2.0 Flash API の2種類を試験しました。

しかし、いずれも課題が生じました。

- **OPUS-MT**：学術的な日本語の翻訳品質が極めて低く、Primary 一致率は 3.1% に低下
- **Gemini API（初期版）**：翻訳成功率が 46% にとどまった。原因を分析すると、① 機関リポジトリ固有のボイラープレートテキスト（「本リポジトリは本学で生産された…」）が要旨に混入、② 英語タイトルと日本語要旨を一括翻訳したため Gemini が英語部分だけを処理、の2点が判明

これらを修正した改良版 Gemini（v4）では Primary 一致率 22.7%、Top-3 Hit 率 **37.1%** を達成し、Top-3 では v2 を初めて上回りました。しかし全 249 万件を API 処理する場合のコスト（約 77,000 円・約 12 日間）を考慮すると、実用上の課題が残ります。

### v4：SciBERT の評価

英語学術論文に特化した **SciBERT** との組み合わせも評価しました。しかし Primary 一致率が 5〜7% まで低下しました。SciBERT は英語のみで学習されており、多言語対応能力がないためです。翻訳後のテキストを使っても、OpenAlex Topic の説明文との意味的類似度が正しく機能しませんでした。

### v5：multilingual-e5-large + BM25（最終推奨手法）

SciBERT の代替として **`multilingual-e5-large`**（560M パラメータ、1,024 次元）を評価しました。e5-base と同じ多言語対応設計を持ちながら、より大きな表現容量を持つモデルです。

結果は予想を超えるものでした。

| 手法 | Primary 一致率 | Top-3 Hit 率 |
|---|---|---|
| v1（e5-base） | 20.6% | 34.0% |
| v2（e5-base + BM25） | 22.7% | 35.1% |
| v4（Gemini翻訳 + e5-base） | 22.7% | 37.1% |
| **v5（e5-large + BM25）** | **25.8%** | **41.2%** |

翻訳不要・無料・ローカル実行のまま、v2 比で Primary +3.1 ポイント、Top-3 Hit 率 **+6.1 ポイント**という大幅な改善を達成しました。

## 評価方法について

**正解ラベルの作成**  
1,000 件のサンプルから Claude API を用いて 97 件の正解ラベルを作成しました。各論文に対して埋め込み検索の上位 20 件の Topic 候補を提示し、最も適切な Topic を選択させる方式です。

なお、この方法にはバイアス（埋め込み検索の上位候補に依存する）が存在します。正解ラベルの外に正解が存在する可能性があるため、今後の人手評価が重要です。

**評価指標**  
- **Primary 一致率**：付与された primary_topic が正解ラベルと完全一致した割合
- **Top-3 Hit 率**：正解ラベルが上位 3 件の Topic の中に含まれた割合

Top-3 Hit 率は、実際の活用場面（論文推薦・関連研究発見）での有用性をより直接的に反映します。

## システム構成

本システムは Python で実装し、以下のライブラリを使用しています。

- **埋め込みモデル**：`sentence-transformers`（HuggingFace Transformers）
- **ベクトル検索**：`faiss-cpu`（Apple Silicon MPS 対応）
- **BM25**：`rank-bm25`（CJK バイグラム対応）
- **実行環境**：Mac mini M4（RAM 16GB）で動作

ソースコードは GitHub で公開しています。  
→ [KKasama/OpenAlex-Topics-assignment-for-IRDB2](https://github.com/KKasama/OpenAlex-Topics-assignment-for-IRDB2)

## 出力フォーマット

各論文に対して以下の情報が出力されます。

```json
{
  "work_id": "https://openalex.org/W...",
  "primary_topic": {
    "id": "https://openalex.org/T12345",
    "display_name": "Computational and Text Analysis Methods",
    "subfield": "General Social Sciences",
    "field": "Social Sciences",
    "domain": "Social Sciences",
    "score": 0.8127
  },
  "topics": [
    { "id": "...", "display_name": "...", "subfield": "...",
      "field": "...", "domain": "...", "score": 0.8127 },
    ...（上位3件）
  ],
  "method": "v4_ensemble"
}
```

Topic・Subfield・Field・Domain の 4 階層すべてを出力することで、分野横断的な集計・分析が可能です。

## 今後の展望

**① 人手評価（実施予定）**  
200 件のサンプル（4 ドメイン各 50 件）について、専門家による人手評価を実施します。v1（現行 OpenAlex）と v5 を比較し、改善効果を定量化します。

**② 全 249 万件への適用**  
人手評価の承認後、IRDB の全 249 万件に v5-e5-large + BM25 を適用します。処理時間は約 56 時間（Mac mini M4 で連続稼働）を見込んでいます。

**③ OpenAlex へのフィードバック**  
付与データと手法を OpenAlex チームに提供し、日本語論文の Topics 精度向上に貢献することを目指しています。

**④ ファインチューニング（長期目標）**  
人手評価で蓄積した正解ラベルを活用し、日本語論文に特化したファインチューニングを実施することで、さらなる精度向上を図ります。

---

## まとめ

日本語論文への OpenAlex Topics 自動付与において、**`multilingual-e5-large` + BM25 アンサンブル**が現時点で最良の手法であることを示しました。主なポイントは以下のとおりです。

- 翻訳不要・無料・ローカル実行で Primary 一致率 **25.8%**、Top-3 Hit 率 **41.2%** を達成
- 機械翻訳は翻訳品質の制約から現時点では有効でなかったが、高精度翻訳モデルの登場により将来的な改善が期待される
- SciBERT（英語専用モデル）は多言語タスクに不適合
- モデルのサイズアップ（e5-base → e5-large）が翻訳より効果的

本研究が、日本語学術コンテンツの国際的な発見可能性向上に貢献できれば幸いです。
